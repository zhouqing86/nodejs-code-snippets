# 后台能力提示词

共同前提：[公共契约](00-shared-contract.md)、A03/A04，以及服务状态机规格。

## A10 — 主进程调度服务

**输入**：工具身份契约、SQLite 仓储、本阶段实施授权。

**可直接发送的提示词：**

实现主进程拥有的调度服务。任务身份由“工具 + 任务”组合唯一确定，保存 cron 计划、启用状态、最近执行时间/状态等信息。执行函数只由受信任主进程代码注册；renderer 不能提交脚本、函数、命令或任意文件路径。

支持注册、启用、禁用、取消、查询任务与执行状态。先校验 cron 是否合法且存在未来执行时间，再持久化；重复注册明确拒绝或按已批准幂等语义处理，不生成重复计划。启用前需要存在主进程 handler。

启动时先注册 handler，再恢复启用任务；无 handler 的任务显示原因且不执行。崩溃遗留的运行记录应被识别为中断/失败，不长期显示运行中。退出时停止未来触发，并定义在途执行的处理方式；不宣称退出后仍可调度。

同一任务不可重叠执行，失败要隔离，不能击穿服务；记录执行起止和结果但不记录秘密。超时是运行管理状态，不等于底层 Promise 被终止。采用协作取消、隔离执行或明确保留占用等方案，证明不会因超时提前解锁而与未结束的旧执行重叠。此项是目标质量要求，不是旧实现保证。

明确时区、夏令时、休眠唤醒、错过触发的策略。MVP 可选择恢复后只执行下一次而不补跑，必须记录；不承诺分布式 exactly-once。暂不要求完整调度管理 UI，只提供受控状态查询和最小验证入口。

**验收**：合法/非法 cron、重复任务、缺 handler、启用/禁用/取消、重启恢复、崩溃恢复、慢任务防重叠、超时、异常、退出、时间变更策略。测试时钟与调度适配器可注入，关键路径还需真实进程冒烟。

## A11 — 通知服务与状态机

**输入**：主进程服务与存储基础、A10 可用但通知逻辑不依赖 renderer 存活。

**可直接发送的提示词：**

实现应用内通知服务，面向工具或后台任务。通知包含身份、来源工具、可选任务身份、严重级别（warning/error/critical）、标题、正文、去重键、可选元数据及时间信息。

状态为 active、acknowledged、snoozed、resolved、cancelled。明确实现以下规则：

- 新建为 active；active 可确认、延后、解决或取消。
- acknowledged 仍未解决，可延后、解决、取消，不视作已清除。
- snoozed 到期回到 active，也可解决或取消。
- resolved/cancelled 为终态，不能编辑正文或重新激活；重复同一终态操作可按声明的幂等语义处理。
- 延后时长必须有限且为正值。终态清理计时器与去重占用；重启恢复未来延后，已到期的应恢复 active。长延时不能受底层定时器上限影响。
- 有效未终结通知的相同去重键不会重复创建；去重域按来源约束，避免不同工具互相覆盖。旧通知终结后允许产生新的同类事件。

列表按稳定时间顺序返回。计数中分别报告 active、acknowledged、snoozed；actionable = active + acknowledged，严重级别角标只统计 actionable，不计 snoozed 和终态。主进程生成可信快照，UI 只展示。

操作包含创建、更新内容、确认、解决、取消、延后、列表、计数与变更订阅。UI 仅获得必要消费操作；来源不能靠任意 renderer 字段冒充。所有订阅能卸载。

**验收**：完整合法/非法迁移矩阵、幂等、去重生命周期、计数、延后到期、重启与长延时、更新终态被拒绝、坏 payload、订阅清理。数据库写失败不得向 UI 伪报成功。

## A12 — 通知中心、角标与工具深链

**输入**：A02 设计、A10/A11、桌面双窗口 shell。

**可直接发送的提示词：**

实现通知中心工具：查看通知、按严重级别/状态筛选、确认/解决/取消/延后，以及对来源工具的受控跳转。提供空态、加载、失败与操作反馈；元数据不直接当 HTML 或任意导航执行。

浮动入口按 warning/error/critical 显示 actionable 计数，零时隐藏，可采用高数值封顶文案。角标点击不触发入口的普通切换，而是打开面板、选择通知中心并应用相应严重级别筛选。普通入口点击仍是面板显示/隐藏。

处理面板未创建、隐藏、尚未就绪和重复点击的情况：跳转请求在正确窗口就绪后交付，未知工具或筛选值拒绝并可恢复。不因 React 重挂载重复订阅；多窗口初始快照与实时更新保持一致。

用一个仅开发/测试环境可用的受信任示例任务，演示调度器 → 主进程通知 → 持久化 → 角标 → 筛选深链 → 延后/解决。生产构建不暴露任意测试通知生成器。不自动给所有 AI 失败创建通知，除非另行确认产品规则。

**验收**：真实 Electron 中完成端到端链路，确认数值、筛选、重启与事件卸载。明确这里只保证应用内通知；系统 Toast、声音或后台 OS 服务是单独能力，不能用网页模拟冒充。
