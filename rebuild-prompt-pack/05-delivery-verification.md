# 验证与发布提示词

共同前提：[公共契约](00-shared-contract.md)、A01–A12 的阶段产物。

## A13 — 行为、安全与视觉验收

**输入**：接收方自己的代码、规格、阶段记录和测试环境；不需要旧仓库。

**可直接发送的提示词：**

请独立审计当前实现是否满足产品规格，先报告差距和验证计划，再在获准范围内补测试或修复。不能因为功能看起来存在就认定完成，也不能把规格中未批准的增强项列为已有承诺。

建立分层证据：

1. 单元：注册表校验、日期区间、提示数据选择、通知状态机、调度防重叠、错误映射。
2. 仓储/服务集成：真实 SQLite 迁移、事务、去重、重启恢复、图片引用；主进程 AI 使用本地模拟端点。
3. UI 行为：输入校验、选择/保存/删除、过滤、空态、加载、失败、复制、键盘路径。
4. Electron 端到端：双窗口交互、拖拽与点击、通知角标与深链、生产资源加载、数据重启持久化。
5. 视觉：经批准的设计与实际截图逐状态对照；默认/紧凑尺寸、长文本、滚动与焦点。浏览器只能验证渲染部分，透明窗、多屏、缩放和系统安全存储要在真实桌面验证。
6. 安全：renderer 无直接 Node/密钥/数据库能力；拒绝未知 IPC、错误来源、越权资源、恶意路径、危险链接、Markdown 注入；凭据不回读、不出现在日志。

明确 fake clock、mock IPC、模拟 AI 与真实系统的边界。核心测试应能在你破坏相应行为时失败，不用全 mock、只测实现细节或固定 sleep 来制造绿色结果。合成数据覆盖空库、跨月/闰日、长内容、坏输入、存储/网络失败、超时、重启。

若测试要调用真实 AI、访问远端或产生费用，先取得专项批准。所有实际命令和结果列明；未执行的检查标记 not-run 或 blocked。

**验收**：输出需求追踪表，逐项 pass/fail/blocked；阻塞项有可行复验步骤；重大失败不能用“其他测试通过”覆盖；未批准的修复不擅自实施。

## A14 — Windows 构建、发布与移交

**输入**：A13 报告、接收方打包/签名政策；发布操作须单独授权。

**可直接发送的提示词：**

请准备 Windows 首发交付，先生成发布预览与风险清单。分开验证开发启动、生产构建、安装包/便携包运行；原生 SQLite 的 Electron ABI、打包资源和应用数据路径必须实际检查。

明确新品牌、应用标识、图标和安装体验。签名证书及凭据通过接收方安全系统提供，不进入聊天、源码或测试产物。没有签名时说明限制，不伪称可信发布。

测试安装/卸载、便携运行、首次启动、升级迁移、关闭/重开、本地数据保留策略、缺 AI 配置、无网络。不能把“打包成功”等同于“安装后可用”。没有第二台机器时明确只在当前环境验证；macOS/Linux 不在保证范围内。

交付独立实现的源码、锁定依赖、测试、构建脚本、用户说明、开发说明、架构决策、数据字典、隐私与 AI 外发说明、第三方声明、已知限制和下一步计划。说明备份/恢复边界，先保护数据再升级。不得混入任何原组织配置或素材。

**验收**：最终矩阵逐项给证据；AI 可用性、本地功能和发布包分别结论；所有 fail/blocked 明确显示。发布、上传安装包、推送代码、创建或合并 MR 都要分别确认。

## 接收方最终验收清单

- [ ] 原创品牌与已批准依赖，无旧组织资产/配置。
- [ ] 浮动入口可拖拽、可点击，面板隐藏后可恢复，基本键盘路径可用。
- [ ] 注册新内置工具无需改面板核心；错误契约被拒绝。
- [ ] 密钥只在主进程受保护，renderer 不能回读或直接访问 Node/SQLite。
- [ ] 无真实 AI 凭据也可通过确定性模拟完成演示。
- [ ] 翻译润色、历史选择后更新、搜索/删除/清空、保存失败处理可验证。
- [ ] Work 事项、引用、跨日休假、Vacation、Achievement、日/月总结可验证。
- [ ] 调度恢复、防重叠、失败、超时与退出策略有证据。
- [ ] 通知状态机、去重、计数、延后恢复与角标深链有证据。
- [ ] 紧凑布局、空态/错误、无障碍基础和 Markdown/外链安全有证据。
- [ ] Windows 生产包实际启动并使用真实本地数据库。
- [ ] Skill 模拟演练通过且远程写入默认关闭。
- [ ] 未验证项未被勾选；数据外发、许可证与发布均经接收方审批。
