# 应用基础提示词

所有任务均受 [公共契约](00-shared-contract.md) 约束。每次只执行一个编号。

## A01 — 产品边界与阶段规格

**输入**：公共契约、接收方项目参数、这份任务。

**可直接发送的提示词：**

请为一个全新桌面助手建立独立产品规格。用户通过常驻浮动入口打开工具面板，使用翻译润色、日常规划及通知中心。数据本地保存；AI 是可配置且可关闭的外部能力。研发 Skills 在开发环境运行，不嵌入应用。

请输出：

1. 用户场景、功能地图、术语表、范围与非目标。
2. 已确认要求、建议与待决问题；明确哪些可缺省、哪些阻塞实现。
3. 两个层次的迭代：先有可运行的桌面 shell、存储及一个工具，再建设完整规划与后台能力。
4. 需求到 A02–A14 的追踪表，并给每项要求稳定编号。
5. 架构决策：主进程、preload、renderer、工具、仓储、后台服务的职责；不必沿用任何旧目录或命名。
6. 数据实体：设置、AI 历史、计划事项、引用/图片、调度定义/执行记录、通知；区分领域日期和时间戳。
7. 依赖候选与审批清单、Windows 原生数据库模块的构建风险。

功能基线应覆盖双向中英翻译润色和历史复用，Work/Vacation/Achievement 三类规划视图，日/月总结，受信任内置工具注册，cron 调度，通知去重、延后与严重级别角标。不把高级自主代理、Canvas 或云协作加入基线。

**验收**：所有后续阶段都有输入和产物；没有假定可访问旧仓库；没有静默创建工程、安装依赖或调用远端。只完成规格并请求批准。

## A02 — 独立视觉与交互设计

**输入**：公共契约、A01 已批准规格；接收方可选的授权视觉参考。

同时使用 [P03 工程与 UI 标准](10-engineering-ui-standards.md) 的已批准基线。默认/中等紧凑尺寸之外，还须验证 420×640 窄窗口；若批准了更大的最小尺寸，记录原因与明确偏差，不静默略过窄窗口要求。

**可直接发送的提示词：**

请为上述桌面助手设计原创 UI。没有获批参考时先提出自己的方向并请求确认，不能索取旧应用截图来复制。整体应轻量、现代、信息密度适合桌面工具：低干扰背景、清晰分层、节制的主色、可读文本、紧凑但可操作的控件。

请交付可实现的视觉规格而非直接写 UI：

- 浮动入口和通知角标、可调整尺寸面板、工具导航、设置入口的布局与行为；
- 翻译页的输入/结果、动作栏、可检索历史；
- My Day 的 Work/Vacation/Achievement 切换，日历、列表、编辑区及总结区；
- 通知中心的状态/严重级别筛选、操作、空态和来源跳转；
- 设置页的 AI 服务参数及只显示配置状态的密钥区；
- 设计 tokens：语义色、字号、间距、圆角、阴影、聚焦与禁用状态；
- 默认与紧凑窗口尺寸、最小可用尺寸、滚动分区和溢出规则。可从约 1000×720 与 720×560 逻辑像素开始评估，这些是设计起点而非旧产品像素契约；
- 页面状态矩阵：空、加载、有数据、错误、只读、禁用、选中、长文本；键盘路径、可访问名称、焦点可见性和对比度。

将参考中的元素标记为接受/调整/拒绝；未决问题单列。明确哪些界面使用真实桌面验证、哪些可先用浏览器验证。

**验收**：有状态矩阵与组件行为规格；紧凑布局不隐藏主要动作；外观不是只有一句“做现代 UI”；设计批准前不实施 UI。

## A03 — 安全桌面骨架与本地存储

**输入**：公共契约、已批准 A01/A02、依赖安装授权及本阶段实施授权。

目录和层间依赖遵循已批准的 [P01 蓝图](08-repository-blueprint.md)，工程门禁遵循已批准的 [P03 标准](10-engineering-ui-standards.md)。

**可直接发送的提示词：**

请独立建立 Windows 优先的 Electron + React + TypeScript 应用。实现分离的浮动窗口和工具面板：浮动窗口透明、无系统边框、置顶；点击切换面板，拖动与点击可区分，右键可打开经批准的本地菜单，键盘可打开面板。面板可隐藏、恢复、调整尺寸，并在多屏与缩放情况下保持可找回。关闭面板与退出整个应用的语义必须明确。

建立窄类型 preload bridge、共享跨进程契约和运行时校验；窗口配置保持上下文隔离并关闭 Node 集成。开发服务器地址与生产资源加载分别处理，不能因开发配置使生产加载任意远端内容。限制新窗口、导航和外部链接。

建立本地 SQLite 存储服务、版本化迁移、类型仓储、统一结果/错误模型。数据库放接收方应用数据目录；UI 不知道任意磁盘路径或 SQL。先实现非敏感设置与最小验证实体，后续按阶段扩展 schema；不用双套互相分歧的建表逻辑。

建立开发、类型检查、构建和测试入口。原生数据库模块需要分别适配开发测试运行时与 Electron 运行时；记录 ABI 重建步骤，不用浏览器数据库 mock 证明原生数据库已可用。

**验收**：开发启动与生产构建各有证据；点击/拖拽互不误触；隐藏后可恢复；持久化设置重启可读；重复启动迁移无损；恶意 IPC、越权导航被拒绝；至少一次真实 Electron 与真实 SQLite 冒烟。未能执行的环境检查标记 blocked。
