# 跨组织独立重建提示词包

这套文档用于让另一团队在**无法访问原仓库**的情况下，从产品行为与工程契约出发，独立实现一个桌面工具平台及其 AI 辅助研发工作流。它不是源码迁移、逐行复刻方案，也不保证像素一致或数据文件兼容。

## 分享前提

- “不传源码”不自动等于“允许传产品设计”。先由有权人员确认需求、流程和架构抽象可对外分享；不确定的条目应删去或重新抽象。
- 只分享本目录经批准的文档，不分享上级目录、原仓库、截图、运行日志、知识图谱、数据库、附件或配置。
- 文档未携带原实现代码、内部服务地址、组织映射、真实用户数据或凭据。接收方使用自己的品牌、授权素材、服务端点和安全配置。
- 第三方框架和工具必须在接收方独立进行许可证、安全和采购审查；本包不转授任何第三方权利。

## 两条路线

1. **应用路线**：浮动桌面入口 → 工具面板 → 本地数据 → 翻译润色 → 日常规划 → 调度 → 通知 → Windows 发布。
2. **工作流路线**：需求拆解 → 开工规格 → UI 设计 → 实现与测试 → MR 评审与交付 → 知识和 Skill 质量治理。

Skill 是供开发 AI 调用的工作流，不是需要嵌入桌面应用的运行时插件。两条路线可以分开建设。

## 如何交给另一个组织的 AI

1. 先向接收方 AI 提供公共契约，完成参数确认；缺省使用全新品牌、本地模拟 AI、Windows 首发、离线工作流。
2. 每次只发送**一个编号的提示词**及所需已批准产物。不要一次要求实现整个包。A02/A03、S02–S05 应持续引用已批准的 P01/P03；S06 使用 P02 的具体集成流程。
3. 每阶段先检查输入，再生成计划和验收，获得本阶段实施授权后才实现。创建 Issue、推送、合并、关闭 Issue 等仍需要分别确认。
4. 只有本阶段验收通过，或你明确接受其阻塞与风险，才进入下一阶段。
5. 新对话只需提供公共契约、当前提示词、接收方自己生成的规格与阶段交接记录。不需要原仓库。

**首次消息可直接发送：**

> 我会按编号提供一系列独立重建任务。你不能访问也不应索取旧仓库。请先遵守附件中的公共契约，建立项目参数与阶段交接记录，不要一次实现所有功能。现在只执行 A01 的规格工作。任何外部依赖安装、真实数据外发、远程写操作都必须按契约单独确认。

## 范围说明

本包保留当前应用的主要行为：桌面双窗口入口、可注册工具、AI 配置与历史、双向中英翻译润色、日常规划、假期、成就、日报月报、后台调度、应用内通知中心。

为独立重建补充的**推荐质量要求**包括：更严格的 IPC 校验、可见错误与数据外发提示、路径约束、超时语义、完整阶段验收。这些是目标实现的要求，**不是原产品已验证的安全保证**。接收方应自行设计，不复刻历史缺陷。

默认不含：Canvas、远程插件市场、支持代理/自主运维、多用户协作、云同步、系统级邮件或聊天服务集成、关机后后台执行、macOS/Linux 发布保证。引用邮件或聊天链接不意味着接入那些服务。

## 最后交付的不是“看起来完成了”

接收方应交付可运行应用、自己生成的完整源码与测试、安装说明、数据与安全说明、独立 Skill 包及评估报告。这里的“不能传源码”针对原仓库；接收方应正常拥有自己独立实现的源码。

本包只完成了仓库事实核对和文档检查，未在另一个组织实际运行全部重建流程。最终功能与安全能力必须由接收方验收证明。
