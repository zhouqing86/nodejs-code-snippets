# 工程与 UI 标准手册

这是一套新写的中性工程基线，不是旧设计系统的导出。安全与授权规则为硬约束；具体视觉数值是建议默认值，须由接收方在 A02 批准后成为项目标准。它们不保证像素复刻，也不代表原项目已全部做到。

## P03 — 批准工程规则、视觉基线和 Issue 模板

**执行时机**：A01/P01 后，A02 消费本文件形成设计，A03 起实施；已有代码则先评估差异，不自动重构。

**输入**：[公共契约](00-shared-contract.md)、产品范围、目录映射及接收方标准。

**可直接发送的提示词：**

请基于以下基线形成接收方自己的工程规范、设计系统、Issue/实施/验收模板与质量 gate。明确哪些采用、哪些调整、哪些仍阻塞；有更强的组织规范则采用更强规范并记录理由。先批准规则，不直接生成所有业务功能。

### 1. 工程硬约束

- strict TypeScript；边界使用 unknown 和校验，不以 any 绕过契约；代码标识、注释和测试名用英文。
- main/preload/renderer 的请求、返回、错误和订阅成套维护；主进程实施运行时校验，不信任类型声明或 UI 禁用状态。
- 业务规则在纯逻辑/服务中可测试；组件负责展示与交互，不混入 SQL、系统访问或外部密钥。
- 数据库 schema 由单一迁移入口维护；已发布迁移不重写；多步骤操作需要一致性和失败恢复策略。
- UTC 审计时间与本地业务日期分开，cron 时区/错过触发/超时策略显式化；测试允许时钟注入。
- 预期业务失败使用稳定错误类别；UI 给可操作提示。未经脱敏的异常不显示给用户或写入运行记录。
- 异步动作防重复、可显示加载和失败；过时响应不能覆盖新选择；组件卸载清理订阅和计时器。
- 不吞保存失败、不把失败显示成空数据、不把生成成功等同保存成功；草稿与未保存结果要保留。
- 新依赖需批准并声明，不依赖偶然存在的传递包；原生模块明确 Node/Electron 测试运行时和 ABI。
- 实际定义检查入口：类型、格式/静态检查、单元、集成、Electron E2E、构建、打包。具体脚本由项目创建后核实，不虚构命令已存在。

### 2. 新的视觉默认值（待批准）

采用安静、清晰、工具型界面，不复刻任何品牌。优先系统 UI 字体，中文使用平台合适回退，不携带未授权字体文件。

| 类别 | 建议基线 | 规则 |
|---|---|---|
| 背景/表面 | 背景 #F4F6F8，卡片 #FFFFFF | 用层级、边界与间距组织，不到处加重阴影 |
| 正文/次要文本 | #182230 / #475467 | 正文不可使用过浅的占位色 |
| 主色/按下 | #175CD3 / #1849A9 | 主操作有限，不能把全页按钮都设为主色 |
| 分隔/交互边框 | 装饰 #D0D5DD；可操作轮廓 #667085 | 装饰线不能替代可辨识控件边界 |
| 成功/警告/错误 | #067647 / #854A0E / #B42318 | 状态同时有文字/图标，不能仅靠颜色 |
| 文本层次 | 页标题 22/28、分区 16/24、正文 14/22、辅助 12/18 | 单位为逻辑像素字号/行高；重要内容不靠 10px 小字呈现 |
| 间距 | 4、8、12、16、24、32 | 卡片内 12–16；页面 16–24；统一节奏 |
| 圆角 | 控件 6、卡片 10、胶囊按需 | 不混用大量无规则圆角 |
| 控件 | 常规高度 36–40，主要动作 40 | 桌面命中区域建议不小于 32×32；触摸目标建议 44×44 |
| 图标 | 常规 16–20 | 统一风格；纯图标动作必须有可访问名称 |
| 焦点 | 清晰 2px 轮廓与适当偏移 | 不移除 outline 而不提供替代 |
| 动效 | 非必要过渡约 120–180ms | 尊重减少动态偏好，不用动画掩盖加载 |

批准时对**实际前景/背景组合**测对比度：普通文本至少 4.5:1，大文本至少 3:1；必要控件边界与状态指示至少 3:1。不因表里给了颜色就认定所有组合可访问。支持系统文本缩放；暗色模式不是默认基线，另行设计后加入。

### 3. 组件行为标准

| 组件 | 最低契约 |
|---|---|
| 页面头部 | 标题、上下文、少量主要动作；窄屏可换行，不截掉核心动作 |
| 按钮 | 默认/hover/focus/pressed/disabled/loading；加载时防重复，不只换文案 |
| 表单 | 显式 label、格式提示、错误与字段关联；必填/范围规则一致 |
| 输入/结果区 | 可选择文本；长内容独立滚动；编辑结果不被后台刷新覆盖 |
| Tabs | 真正 tab 模式使用语义与方向键；普通切换按钮则不伪装成 tab 语义 |
| 列表/表格 | 选中状态、空态、加载、错误、键盘操作；必要横滚限制在数据区 |
| 对话框 | 标题与动作明确、焦点进入/限制/返回、Escape 策略；危险操作单独确认 |
| 通知卡片 | 严重级别、来源、状态和可用动作可见；终态不提供非法动作 |
| 反馈 | 成功、失败、未保存清楚区分；合适的 live region，不频繁打断读屏 |

日期格、角标、无边框窗口的可点击区域都要有键盘与焦点方案。删除/清空有可理解确认，不用不可读原始异常替代错误界面。

### 4. 尺寸和布局基线

- 标准：约 1000×720；中等紧凑：720×560；窄窗口：420×640，均为可用内容区逻辑像素。
- A02 的 720×560 是设计起点，不替代 420×640 的窄屏检查。默认支持窄窗口的单列布局；如确需更大硬最小尺寸，必须在设计阶段明确批准并记录对本基线的偏差，不能实施后临时跳过。
- 标准尺寸可使用双栏；窄屏将列表/编辑区重排，导航可折叠或横向局部滚动，不能让整个页面横向溢出。
- 长表格允许表格内部横滚，但主要按钮、表单与导航不能依赖横滚才能找到。
- 真实 Windows 验证缩放、多屏、窗口位置、透明入口和可恢复性；网页截图不覆盖这些能力。

### 5. Issue 与实施模板的最低字段

不导入旧 Issue 内容、号码或地址。由接收方按照自己的 backlog 新建以下模板：

| 产物 | 必填信息 |
|---|---|
| 候选 Issue | 用户价值、现状证据、重复/复用结论、范围/非目标、可验证验收、依赖、风险 |
| kickoff 规格 | 精确工作项关联、版本、批准状态、行为/数据/IPC 契约、开放问题、分支建议、验证计划 |
| UI 规格 | 参考评估、尺寸、tokens、组件/状态/交互、无障碍、设计批准、视觉证据计划 |
| 实施计划 | 匹配分支、修改边界、TDD 切片、复用点、迁移/兼容影响、实施授权 |
| MR 说明 | 范围关联、变更摘要、实跑验证、安全/数据影响、截图与限制、未完成项 |
| 完成记录 | 每项验收结果、合并/其他完成证据、已知问题、文档更新与下一步 |

验收用“给定条件—执行动作—可观察结果”表达，至少覆盖成功、非法输入、依赖失败和适用的重启/恢复场景。不要把“添加按钮”当作“完整能力已验收”。UI 工作显式附状态矩阵与两个以上布局层次。

### 6. Ready / Done 与失败门禁

**Ready**：范围和非目标清楚、依赖可用、关键开放问题已解决、验收可执行；UI 有批准设计；权限、数据外发和依赖审批明确。Ready 不自动授权代码修改。

**实现完成**：测试与生产构建有证据；跨层契约和迁移验证；UI 有非空渲染、控制台、资源、状态与尺寸检查；风险和未执行项透明。实现完成不自动授权 push/merge/close。

| 检查 | fail 的例子 | blocked 的例子 |
|---|---|---|
| 工程 | 类型错误、迁移破坏、核心测试失败 | 缺获准原生运行环境 |
| UI | 空白、遮挡/截断主动作、资源缺失、相关控制台错误 | 无法取得浏览器/桌面证据 |
| 安全 | 密钥回读、任意执行、越权 IPC、日志泄露 | 无法在目标 OS 核实安全存储 |
| 发布 | 安装包不能启动或读写数据库 | 缺签名/目标设备验证权限 |

fail 需要修复；blocked 需要补环境/权限或由人明确接受风险，不能改成 pass。设计和快照基线变更需批准，不能通过更新预期掩盖回归。性能阈值在基准环境实测后制定，不能编造旧产品指标。

**验收**：输出获准版本的规范、可复用模板、状态→组件→测试/截图追踪表、检查入口与 gate 报告格式。用一个小 UI Issue 演练 Ready→设计批准→实施授权→red/green→视觉验证→MR 预览；故意制造一次裁切或空白，证明门禁会失败。未批准不得连真实远端演练。
