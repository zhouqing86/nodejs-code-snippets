# 推荐目录结构与文件职责

这是接收方新项目的**建议蓝图**，不是旧仓库目录导出，不含实现代码。目录名可调整，但职责、安全边界和唯一事实来源必须保持。先批准映射，不要为了符合树形图预建大量空文件。

## P01 — 建立项目结构与产物路由

**执行时机**：A01 产品范围批准后、A02/A03 之前；可与 P03 规格工作并行。

**输入**：[公共契约](00-shared-contract.md)、A01 产物、接收方编辑器约定。

**可直接发送的提示词：**

请使用下列蓝图规划接收方自己的目录与文件职责，输出“采用/调整/不需要”的映射、依赖方向和阶段产物位置。只完成规划；获得创建授权后才生成最小目录及规范。根规范作为统一入口，子项目规范只写局部差异；编辑器指令入口引用统一规范，避免多份互相冲突的长文。

目录分为应用运行时代码、开发 AI 工作流、项目事实、产品决策、测试证据、派生图谱和私有运行数据。Skill 与运行时工具不得混放。共享代码只有在真实复用出现后抽取，不建立万能公共层。

### 文件职责与依赖方向

| 边界 | 可以依赖 | 禁止事项 |
|---|---|---|
| renderer | 纯共享契约、UI、类型客户端 | 引入 main/Node/SQLite/安全存储实现 |
| preload | Electron 受限桥与共享契约 | 通用 IPC 透传、数据库逻辑、任意执行 |
| main | 服务、仓储、共享校验、系统 API | 信任 renderer 自报身份或直接执行其代码 |
| shared | 无副作用的类型与纯逻辑 | 引入 UI、密钥、系统 API、连接数据库 |
| 工具 | registry 契约与窄平台能力 | 为新增工具修改 shell 核心分支 |
| Skill | 自身资料与获准共享辅助能力 | 与应用打包、携带真实远程配置或凭据 |

数据库与图片保存在运行时应用数据目录，**不在仓库里**。配置样例只给无敏感值的字段说明；真实本地配置不跟踪。构建结果、依赖缓存、trace、浏览器会话与生成图谱默认排除。可以在审查后提交合成测试基准和脱敏验收报告，但不能据此开放整个证据目录。

### 阶段产物路由

- A01 的产品范围、A02/P03 的设计决策、P01 的结构决策：分别进入规格、设计与 ADR。
- 每个 Issue kickoff 生成唯一规格，含工作项关联、范围版本和批准记录；文件名不依赖真实公司地址。
- 实施计划、测试结果和下一步放阶段交接；截图放私有 artifacts，只在获准报告中引用。
- 当前代码事实在 context；未来计划在 specs/backlog；外部知识在 Wiki。不要用其中一个冒充另一个。
- S01–S09 生成 Skill 与质量资料；P02 生成知识集成指南；图谱只是可再生派生数据，不是规范真相。

**验收**：输出完整职责映射，存在唯一规范入口、唯一 schema/迁移入口和明确产物位置；无重复类型真相；无 renderer 越层导入；私有配置与运行数据不进版本控制；空目录不为数量而建。批准结构更改时记录旧新路径映射，并更新引用与检查。
