# graphify 与 Wiki 集成规范

本文件将 S06 的知识能力落为明确集成任务。graphify 是**优先评估的第三方工具**，不是本包附送的实现。接收方独立获取、审查许可、验证版本；不复制旧 Skill、旧图谱或旧 Wiki。组织不批准时允许受控降级，不能冒称已安装。

## P02 — 建立可追溯的双通路项目记忆

**执行时机**：P01 与 S01 之后，作为 S06 的具体实施任务；可以先用合成样本验证，不依赖应用全部完成。不因 P02 自动安装 Python、软件包或外部服务。

**输入**：[公共契约](00-shared-contract.md)、已批准目录映射、依赖/数据策略、接收方自己的合成代码与文档。

**可直接发送的提示词：**

请建立“代码结构索引 + 来源驱动 Wiki → 可追溯图谱 → 查询与核验”的项目记忆流程。先提交集成计划与安装审批，再实施获批范围。不能把所有项目文档自动传给外部模型。

### 1. 工具与能力探测

- 确认运行环境、已有 graphify 可执行程序/版本、依赖与许可。若需要新 Python 环境或安装包，先报告并请求批准。
- 在获准环境查阅该版本帮助与上游文档，生成实际可运行的命令清单，标记“已验证/该版本不支持/未执行”。不要仅凭本文件示例声称命令可用。
- 核实 AST 结构抽取、文档语义抽取、可选模型提供方及其网络行为。无外部模型审批时仅采用本地可行路径；需要语义推断但无法安全执行时标记缺口，不编造关系。
- 没有凭据不应导致无关本地功能停摆；不在聊天里索要 key，也不能为获得“完整图谱”绕开组织策略。

### 2. 索引范围先于扫描

默认采用**获准目录 allowlist**：应用源码、合成测试、已批准规格/架构文档与脱敏 Wiki。原始文档是否可索引需按来源单独确认，摄取到 raw 不等于获准外发。

明确排除：密钥/环境配置、真实项目映射、数据库、用户图片、日志、浏览器存储、运行记录、依赖目录、构建产物、隔离 worktree、版本控制内部目录和 graphify-out 本身。扫描器默认设置不能替代自己的范围控制；若工具不能保证排除，先构建仅含获准内容的隔离输入，再建图。

首次只用少量合成数据验证排除效果，再扩大范围。不要通过打印被排除文件内容来证明没有扫描秘密。

### 3. Wiki 生命周期

- raw 保存获准来源原文与来源标识，摄取流程只读；修订以新版本与关联关系体现。法定删除/泄露处置按安全策略处理，不受“原文不可变”习惯阻挡。
- 先读取来源并提出摘要/主题/冲突预览，批准后更新 Wiki。每页记录标题、状态、来源、核验时间、主要结论、限制和关联。
- 事实引用可追溯到来源和定位；推断与未知显式分开。冲突并列，不静默择一；已过期结论显示警告。
- 更新主题页时同步索引并追加变更日志；重复摄取不重复建页。语言与命名按接收方约定，不能意外改写原文。
- lint 检查断链、孤页、无来源结论、过期条目、索引和日志遗漏。先报告，主观合并/删除需批准。

### 4. graphify 操作契约

以下为需要**对所装版本核实**的操作形态，不是此刻要求执行的终端命令：

| 意图 | 待验证的工具形态 | 完成证据 |
|---|---|---|
| 首次构建 | graphify 加获准输入目录 | 输入范围、版本、构建指纹、抽取结果与失败项 |
| 增量更新 | graphify 加输入目录及 --update | 新增/变更/删除来源处理是否正确；不支持删除时安全重建 |
| 主题查询 | graphify query 加问题文本 | 起始命中、相关关系与来源定位 |
| 概念解释 | graphify explain 加已存在概念 | 概念依据与不确定部分 |
| 关系路径 | graphify path 加两个已存在概念 | 实际路径及每条边的证据；无路径则明确无结果 |
| 交互浏览/导出 | 本版本支持的 HTML/报告导出 | 本地产物可读，无隐式上传或发布 |

图谱节点/边至少可追溯到来源与抽取批次，区分直接抽取、推断和不确定关系，保留适用的置信信息。记录源集合指纹、代码版本和构建时间，不能只看输出文件修改时间断言新鲜。不导出无需分享的正文片段。

### 5. 查询优先级与回退

项目架构/关系问题：先读取索引状态，选择图谱真实词汇（必要时将用户语言映射为已存在术语）进行 scoped 查询，再读取相关 Wiki 和当前代码核验。回答注明来源与过期风险；静态导入边不代表运行时一定调用，推断边不能冒充代码事实。

对明确的 bug/具体行修改，图谱只作导航，不阻止直接核对当前文件。新文件尚未索引、词汇无匹配、无路径时，明确说明并回到批准范围的文本搜索/文件证据。

CLI 不可用时，可在获准依赖与 schema 已核实的前提下查询现有本地图谱；否则降级为本地文档索引，不安装未批准依赖、不编造遍历输出。两者均不可用则报告 blocked，并提出可执行替代步骤。

### 6. 更新和验证时机

- 获批来源摄取后：Wiki 更新 → lint → 必要时增量图谱更新。
- 架构/契约/关键实现变更后：先核实 context 差异，再更新派生索引；不得自动回写产品决策。
- MR 前检查关联来源是否过期，但图谱构建失败不能被伪装成应用构建失败，两类 gate 分别报告。
- 自动 hook/watch 另行批准，默认关闭；每次范围扩大或启用外部模型都重新审查。

**交付产物**：接收方自己的知识集成指南、已核实命令表、范围清单、Wiki 模板、更新/降级策略和合成验收报告；入口规范中加入何时查图谱、何时读 Wiki、何时核实代码的简明路由。

**验收**：用合成代码模块关系和两份有冲突的文档验证建图、查询、解释、路径、来源追溯、重复摄取、更新/删除、陈旧检测和 lint；用无真实秘密的排除哨兵验证范围；关闭 CLI/网络后验证回退。未执行或不支持的能力逐项标记，不声称本包已在当前或接收方环境验证了 graphify 安装。
